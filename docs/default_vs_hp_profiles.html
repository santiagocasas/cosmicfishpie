Default vs high-precision Boltzmann profiles#

Summary#

CosmicFishPie ships two kinds of Boltzmann-solver settings for the class and camb backends: relaxed default.yaml profiles, used automatically when no class_config_yaml / camb_config_yaml is given, and the paper-validated nuvalidation_hp.yaml profiles (Archidiacono et al., arXiv:2405.06047v1). This page records a rough check of how much the cheap default profiles change a photometric Fisher forecast, compared with the high-precision ones.

Findings:

  • CAMB: default.yaml reproduces nuvalidation_hp.yaml to better than 1% on every marginalised 1-sigma error (below 0.04% unmarginalised), at about 4.6x lower Fisher cost (30 s vs 138 s).

  • CLASS: default.yaml differs from nuvalidation_hp.yaml by up to about 6% on the marginalised cosmological errors (below 0.3% unmarginalised), at about 1.7x lower cost (111 s vs 186 s).

  • Cross-code: with the nuvalidation_hp profiles, CLASS and CAMB agree to below 1% on all marginalised errors. With the default profiles they differ by up to about 6.5%, and that gap comes almost entirely from the CLASS default.

Decision: the default.yaml profiles are accurate enough for exploratory work and for the MCMC / likelihood runs where Fisher-level accuracy at the few-percent level is acceptable, and they are used there. Use nuvalidation_hp.yaml when the forecast itself is the result. CAMB defaults in particular give essentially the same constraints at a fraction of the cost.

This is a rough check, not a validation. See Caveats.

The forecast setup is the same for all four, in the style of the case-02 photometric campaign:

  • Survey: Euclid-Photometric-Paper-Pessimistic, observables GCph + WL, with the photometric galaxy-clustering tracer set to matter (P_mm).

  • Specs: common_specs_paper_w0wa_fixed_mnu_Neff.json, w0waCDM with mnu and Neff fixed.

  • Free cosmological parameters: Omegam, Omegab, h, ns, sigma8, w0, wa.

  • Nuisance parameters are also free, so they enter the marginalised errors: photometric bias b1-b10 and intrinsic alignment AIA, etaIA.

  • The backend YAML is passed explicitly through <code>_config_yaml.

For each case the script times one fiducial cosmology evaluation (a cold call plus warm calls) and then one serial FisherMatrix.compute(). Parallel derivative evaluation was not used, so timings are single-process wall times, not the best achievable. Each case ran as its own 16-CPU job on JURECA with OMP_NUM_THREADS=16.

The driver script lives outside this repository, in the cjfp-data job repository, as jobs_punch/compare_backend_profiles.py (subcommands run, all, compare). The discrepancy plots come from cosmicfishpie.analysis.plot_comparison.ploterrs.

Recommendation#

  • CAMB: use camb/default.yaml for exploration and for MCMC chains. It matches the high-precision profile to well under 1% at a fifth of the Fisher cost.

  • CLASS: class/default.yaml is acceptable for exploration and MCMC chains where a few-percent difference in the constraints is tolerable. Errors on Omegam, sigma8, w0 and wa are up to about 6% different from the high-precision result. Use class/nuvalidation_hp.yaml when the CLASS Fisher is itself a result or is compared against CAMB.

  • When quoting a CLASS-vs-CAMB agreement, state which profiles were used. Agreement at the percent level needs the high-precision profiles on both sides.

Caveats#

  • Nuisance parameters. These Fishers marginalise over photometric bias (b1-b10) and intrinsic alignment (AIA, etaIA). They are therefore not identical to the fixed-nuisance convention of the case-02 campaign, and the marginalised percentages should not be compared one-to-one with those results.

  • Confounded CLASS settings. z_max_pk is 4.0 in the CLASS high-precision profile but 5.0 in the default, and tau_reio and use_ppf also differ. The CLASS discrepancy is therefore not attributable to the precision parameters alone. A controlled test would change one group of settings at a time. This was not done.

  • Single fiducial, single configuration. One fiducial cosmology, one survey and one derivative scheme. Percent-level Fisher agreement does not guarantee the same agreement for posteriors that probe far from the fiducial point.

  • Timings. Serial Fisher, one run per case, on a shared cluster. Treat the ratios as indicative, not as benchmarks.

  • Not a validation. The numbers describe how the default profiles compare with the high-precision profiles. They do not show that either is correct against an external reference. For that, see Backend validation.
